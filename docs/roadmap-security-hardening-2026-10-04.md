# 安全加固下期路线图（P2×8 项固化，2026-10-04）

- **来源**：《功能生产化综合验收评审意见书》P2 项 + 整改回签章移交项
- **排期口径**：H1 下期（约 3 人周，含测试）；各项相互独立，可按优先级裁剪
- **总原则**：延续效率-安全平衡——全部复用既有组件与通道，禁止引入全人审/全阻断式极端

| # | 项 | 范围 | 估算 | 出口判据 |
|---|----|------|------|----------|
| P2-1 | **Agent 级 Kill Switch + 熔断阈值** | orchestrator 增加 pause_agent/kill_all（管理端按钮，走 agent:update 权限+审计）；熔断补步数上限/连续失败率阈值（runtime 循环内计数，触发自动暂停+告警） | 3d | Kill Switch 演练：kill 后该域全部调用立即拒绝且审计留痕；熔断触发有告警 |
| P2-2 | **注入红队例行化 + Bad Case 飞轮** | 季度红队流程进 runbook；fallback 触发/人工接管 → 脱敏 → 自动回补 injection_testset.json（脚本化） | 2d | 测试集用例数只增不减；每条 fallback 案例可在测试集中溯源 |
| P2-3 | **Agent/Skill 级 Shadow 灰度** | runtime 增加 shadow 模式：新 Agent/Skill 接收真实流量副本但执行结果仅记录对比（不回用户）；对比报告（差异率/超时率）进管理端 | 4d | 新 Agent 上线默认 Shadow ≥1 周，对比报告达标才可切流 |
| P2-4 | **行为基线与异常检测** | 单任务调用次数/数据量/外发域名基线（按域统计进 operation_logs 聚合）；异常（突增 N 倍/新外发域名）→ 告警 | 3d | 基线报表进管理端；注入红队用例的异常调用能被检出 |
| P2-5 | **MySQL 备份/恢复演练** | mysqldump 每日全量 + binlog 增量（cron/脚本）；恢复 RTO/RPO 定义；演练剧本进 runbook | 2d | 恢复演练实测：RTO ≤ 30min，数据一致性核对脚本通过 |
| P2-6 | **第三方 MCP 内容审查** | 登记时校验 manifest 签名/校验值；工具描述变更 → 自动重新人审（rug pull 防护）；静态审查清单（描述与行为一致性） | 3d | 未过审的 MCP server 工具不可注册；描述变更未重审即拒绝调用 |
| P2-7 | **全成本核算报表** | llm.tokens 审计聚合 × 单价 → 按域/按用户/按周期的成本报表；人工接管时长（审批等待）统计；组件复用次数 | 3d | 管理端报表页；单任务全成本可查 |
| P2-8 | **会话竞态压测** | 多 worker + WS 多路复用 + 并发 join/leave 的竞态压测（复用 multireplica 口径）；修复检出问题 | 2d | 压测报告：无串话/无状态覆写 |

## 依赖与顺序

P2-1（熔断）独立先行；P2-3 依赖 P2-4 的基线数据；P2-2 随任一阶段持续执行；P2-5/6/8 运维并行。

## 与放行意见的关系

本路线图为**放行后的持续加固计划**，不阻塞"公网生产级"放行；P2-5（备份）建议与 TLS 割接同窗口完成。
