## 1. 现状盘点（定制化视角的能力与缺口）

### 1.1 已有基础（可直接复用的地基）

| 资产 | 现状 | 定制化改造中的角色 |
|------|------|------------------|
| 治理面 AgentGovernor | 工具调用统一通道（RBAC/schema/dry-run/分级审批/审计/限流） | **定制生效的执行点**——配置覆盖在此读取即可全局生效 |
| 工具注册表 tools_v2 | 进程内注册 + 目录 API（GET /agent-ops/tools）+ 调用统计 | 工具启停/风险分级改造的操作对象 |
| Skill 加载器 | YAML 目录**热加载**（文件级）、惰性白名单校验、目录 API | 管理端编辑器直接写目录即可生效（加载器零改造） |
| 工作流引擎 | 3 条硬编码 builder + 确定性节点 + interrupt 人审门 + Checkpointer | DSL 化的运行时底座；内置模板保留为"出厂模板" |
| 审批链路 | agent_approval_requests + decide 路由 + 审批中心前端 | 定制变更自身的审批通道（放宽类变更走此流程） |
| Redis 版本信号 | RBAC 跨实例版本失效（ensure_fresh 模式） | **定制热更新广播**——同模式实现多实例配置失效 |
| CIOAdmin 页面 | 已有 Agent 状态/系统配置/备份等管理区块 | 定制中心的 UI 落点（新增"Agent 定制中心"区块） |
| 审计哈希链 | 全量操作审计、重启续链 | 定制变更 100% 审计（谁/何时/改了什么/旧值新值） |
| 评测集 runner | 50 用例 + 在线模式（脚本/真 LLM 双模式） | **定制效果验证器**——配置变更后按域跑分对比 |

### 1.2 核心缺口

1. **配置零持久化**：人审分级阈值（如报销 5000 元免审线）、预算上限等硬编码在代码/配置文件，业务调整需发版；
2. **无管理端操作面**：工具启停/风险分级调整、Skill 内容修改、外部 MCP 接入只能改文件或调 API 脚本，业务管理员无法自助操作；
3. **工作流不可配**：三条跨域流程节点/阈值/审批路由写死，业务链路改造 = 重写 builder；
4. **人在环节点不可配**：审批人路由（谁审什么金额区间）、超时策略、免审线全局一刀切，无法按部门/单据类型差异化；
5. **无版本与灰度**：任何配置变更立即全局生效，无历史、无回滚、无灰度；
6. **存量基线未纳管**：已上线的硬编码参数（5000 元免审线、200 万日预算、7/30/90 天保留策略等）需要一次性迁移为定制层初始基线（见 §2.3）。

## 2. 总体设计

### 2.1 分层模型：内置默认 → 定制覆盖 → 运行时合成

```
┌─────────────── 管理端（CIOAdmin · Agent 定制中心）────────────────┐
│ 工具管理 │ 工作流设计器 │ Skill 编辑器 │ 人在环配置 │ Agent 人设      │
└──────────────────────────┬───────────────────────────────────────┘
                           │ PUT /agent-ops/customizations/*（customization:update）
                           │ 放宽类变更 → customization:approve 审批后生效
                           ▼
┌─────────────── 定制层（MySQL 持久化 + 版本历史 + 环境晋升）──────────┐
│ agent_customizations：type/tool|workflow|skill|gate|agent          │
│ + overrides JSON + enabled + version + updated_by + 审计哈希链      │
│ + environment（dev/test/prod）+ 晋升接口（§2.3）                    │
└──────────────────────────┬───────────────────────────────────────┘
                           │ Redis 版本信号（erp:cust:version）失效缓存
                           ▼
┌─────────────── 运行时合成（各执行点读取：内置默认 ⊕ 定制覆盖）──────┐
│ governor.execute：工具启停/风险分级/参数默认值                      │
│ workflows 运行器：阈值/审批路由/节点参数（DSL 实例）                │
│ skills 加载器：白名单/指令模板/护栏                                 │
│ supervisor/场景图：per-agent 预算/模型参数/业务上下文开关            │
└───────────────────────────────────────────────────────────────────┘
```

### 2.2 四条不可突破的治理红线（schema 层锁死，管理端 UI 只暴露允许项）

1. **治理节点不可禁用**：工作流中治理面校验/审计/dry-run 节点不可删除或跳过，只能调参数；
2. **放宽类变更必须审批**：write_low→write_high 收紧可即时生效；反向放宽
   （write_high→write_low、免审阈值上调、新外部 MCP 接入）必须走人审后生效；
3. **定制变更 100% 审计**：旧值/新值/操作人/审批人全量入审计哈希链；
4. **配置带版本与回滚**：每次变更生成版本记录，一键回滚到任意历史版本。

### 2.3 存量基线迁移与环境晋升（评审 R4 整改）

**基线迁移（一次性，F1 交付）**：
- 迁移脚本 `scripts/migrate_customization_baseline.py`：将当前硬编码值以
  "内置默认（代码常量）+ 初始定制覆盖（库中记录，updated_by=system，备注=基线迁移）"
  双写入库，生成迁移核对报告（参数名/代码值/库值/一致✓）；
- 核对清单：报销免审线 5000、支付人审线 10 万、日 token 预算 200 万、
  保留策略 7/30/90 天、FUND_TRANSFER_THRESHOLD 50 万等全部硬编码业务参数；
- 迁移后代码常量降级为"出厂默认"，运行时以定制层为准（合成顺序见 §2.1）。

**环境晋升（dev → test → prod）**：
- 定制记录带 `environment` 字段；导出/导入接口（JSON 快照，含版本与签名）；
- 晋升流程：test 环境 UAT 通过 → 导出快照 → prod 导入（**放宽类条目逐条走审批**，
  收紧类条目直接生效）→ prod 版本记录标记"晋升来源=test 快照版本"；
- 生产导入前自动执行关联评测集（资金/薪酬/合同域强制阻断见 D-4 修订）。

### 2.4 管理端安全（评审 R5 整改）

- **SSRF 防护**（外部 MCP URL 管理端可填场景）：出站 URL 校验——仅允许
  http/https 协议、禁止内网地址段（10/172.16-31/192.168/127/169.254/元数据地址）、
  禁止 IP 直连（仅域名，DNS 解析后二次校验解析结果非内网）、生产环境叠加
  出站域名白名单；
- **防重放**：定制变更 API 要求请求体携带 nonce + 时间戳（5 分钟窗口），
  服务端去重；敏感操作（发布/晋升/回滚）二次确认（前端确认弹窗 + API 幂等键）；
- **定制审批超时与升级**：放宽类变更审批复用 `human_approval_timeout`；
  超时 50% 提醒、100% 超时自动升级至 administrator 并在审批中心置顶；
  超时未批的放宽变更**保持不生效**（失败安全）。

### 2.5 热更新机制（复用已验证模式）

定制写入 MySQL → `INCR erp:cust:version`（Redis）→ 各执行点
`ensure_fresh()`（5 秒节流）检测漂移 → 重载定制缓存。
多实例部署下全部实例 5 秒内收敛，无需重启。
定制层读取失败时自动回退内置默认并显式告警（失败安全，Phase F5.4 演练）。

## 3. 分阶段路线图（5 阶段，修正后总周期 11 人周）

> 资源假设（评审 R6 整改）：**后端工程师 ×1（全职）+ 前端工程师 ×1（各阶段介入）**。
> 关键路径为后端线；前端线（UI/设计器/看板）与后端并行，F3 前端设计器为前端峰值。
> 每阶段退出标准含：技术断言 + **UAT 验收场景**（脚本见附录 A，甲方业务管理员执行）。

### Phase F1：定制化配置中心——治理面可配（后端 2 人周 + 前端 0.5 人周）

**目标**：建立定制层（持久化+版本+审批路由），第一批治理面配置管理端可改。

**退出标准（全部可验证）**：
1. 管理端将任一工具 `write_low→write_high`（收紧）→ 5 秒内全部实例生效，该工具
   后续调用进入人审门（集成测试断言）；反向放宽需审批通过后才生效；
2. 免审阈值（如报销 5000 元线）管理端可调，生效后新单据按新阈值路由；
3. 工具临时停用（如销售下单工具下线）→ 调用返回明确的"已停用"错误，审计记录；
4. 每次变更产生版本记录，回滚到历史版本 API 可用且生效；
5. 多实例收敛 ≤5 秒（Redis 版本信号）；定制变更全量审计；
6. **存量基线迁移完成并出核对报告**（§2.3）；
7. **UAT-F1 两场景通过**（附录 A：工具风险收紧、免审阈值调整）。

### Phase F2：Agent 级定制与业务链路参数化（后端 2 人周 + 前端 0.5 人周）

**目标**：单个 Agent 的人设/预算/业务链路参数管理端可配，不改代码。

**退出标准**：
1. 修改某 Agent 系统提示词（人设模板）→ 该 Agent 下轮对话即按新人设回答（评测集跑分留档）；
2. per-Agent 覆盖：LLM 温度/日 token 预算/工具子集（该 Agent 可用工具清单）管理端可配；
3. 业务链路参数化首批：报销流免审阈值、必填字段（是否强制发票）、上下文采集开关
   （该域编排注入哪些业务数据源）管理端可调；
4. **审批人路由矩阵 v1（与存量审批链关系见 §4.3）**：按「单据类型 × 金额区间 → 审批角色」
   映射表管理端可配，write_high 中断产生的审批任务按矩阵路由至对应角色，
   审批中心按角色过滤待办；
5. 全部覆盖项有变更前后评测对比报告；
6. **UAT-F2 两场景通过**（附录 A：人设定制、审批路由矩阵配置）。

### Phase F3：工作流改造——DSL 化与人在环节点配置（后端 2.5 人周 + 前端 1 人周）

**目标**：工作流从硬编码 builder 升级为声明式 DSL，管理端可视化改造业务链路。

**退出标准**：
1. 工作流 DSL（JSON/YAML）：节点（task / **condition 分支多路路由** / gate 人审 /
   approve / end）/ 边 / 条件路由（按金额/部门字段路由至不同分支——评审 D-2 修订）/
   人审参数（阈值/审批角色/超时）/补偿映射声明式定义；
2. **DSL 校验器**：治理节点缺失、补偿未映射、环检测、未知工具引用 → 拒绝发布；
3. 现有 3 条工作流迁移为 DSL 实例，与硬编码版**行为等价**（同一测试双跑断言）；
4. 管理端可视化设计器 v1：表单式节点编辑 + 流程图预览 + 版本发布/回滚/灰度
   （**粘性路由**：按单据 ID 哈希绑定版本，同一单据全程同一版本，杜绝状态分裂）；
   人在环节点：阈值/审批角色（对接 F2.5 路由矩阵）/超时 per-node 可配；
5. DSL 发布走审批（变更影响面大），发布后自动跑关联评测集
   （**资金/薪酬/合同域低分强制阻断**——D-4 修订）；
6. **UAT-F3 两场景通过**（附录 A：报销流阈值调整发布、条件分支改造）。

### Phase F4：MCP 与 Skill 定制化（后端 2 人周 + 前端 0.5 人周）

**目标**：MCP 接入与 Skill 内容管理端自助化，业务管理员不碰文件。

**退出标准**：
1. 外部 MCP Server 管理端 CRUD + 连接测试 + 工具发现预览 + 白名单勾选 →

5. 全部变更审计 + 评测验证（skill 变更后自动跑关联域评测）；
6. **UAT-F4 两场景通过**（附录 A：外部 MCP 接入、Skill 编辑发布）。

## 4. 关键设计决策（评审 R3/R5 整改细化）

### 4.1 定制层 schema 演进与回滚兼容（S2）

- overrides JSON 携带 `schema_version`；读取时按版本迁移函数链升级到当前版；
- 回滚到历史版本 = 按该版本 schema 原样恢复 + 当前 schema 迁移函数补齐缺省；
- schema 迁移函数纳入单测（旧版本样例 JSON 固定用例）。

### 4.2 审批矩阵与存量三级审批链的关系（R3 整改）

**策略：矩阵路由"前置分流"，存量三级链保留为矩阵的默认分支（共存渐进迁移）。**

1. write_high 人审任务产生时，先查路由矩阵：
   - **命中** → 按矩阵路由至对应审批角色（矩阵分支可配置直达单级审批，
     跳过三级链——即"矩阵优先"）；
   - **未命中** → 落入存量三级链（普通/敏感/高风险，按金额段自动定级）——
     即三级链成为矩阵的 `default` 分支，行为向后兼容；
2. 迁移节奏：F2.5 上线时矩阵默认为空（全部走三级链=现行为）；
   管理端逐步配置命中规则，每次配置自动生成影响面报告（近 30 天同类单据量）；
3. 完全替代三级链的决策**不在本路线图范围内**（需运营数据支撑，列后续评估）。

### 4.3 审批人路由矩阵 schema（F2.5）

```
{ "rules": [
    {"document_type": "reimbursement", "amount_min": 5000, "amount_max": 50000,
     "approve_roles": ["dept_manager"], "fallback": "next_rule"},
    {"document_type": "fund_transfer", "amount_min": 100000,
     "approve_roles": ["cfo", "chairman"], "mode": "any_of"}
  ],
  "default_chain": "legacy_three_level" }
```
- 矩阵变更属**放宽/收紧混合**：新增命中规则=放宽（须审批），删除/收紧=即时生效；
- 规则变更自动生成影响面报告（按历史 30 天单据分布统计命中量）。
