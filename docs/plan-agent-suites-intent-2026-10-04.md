## 四、治理与安全（贯穿）

1. **Skill 生命周期**（工业规范 §5.5）：新 Skill 走 skill_versions 发布审批（放宽类）→ 灰度 → 回退通道；改动绑定 eval（2.4）；
2. **MCP 风险对策**（KB 六风险逐条）：工具投毒→描述变更告警；rug pull→版本锁定；间接注入→untrusted 封装（已建）；过度授权→readonly+表子集；Sampling→不启用；供应链→准入 6 检查；
3. **意图可回退**：任何意图分类失败/低置信 → 默认 query 路径 + thinking 标注"低置信"；
4. **沙箱默认拒绝**：code-exec 工具默认禁用，启用须容器部署+开关+白名单三条件（E2 红线延续）。

## 七、评审委员会裁决意见书（2026-10-04）

**评审方式**：三组（平台架构/产品体验/内控合规）对计划逐批次评审 + 知识库方法论比对（三层货架/渐进式披露/Routing 可回退/准入 6 检查）。

**总体结论**：**批准实施**——计划以知识库"能力三层货架"组织、现状盘点诚实（intent.py 建而未接线等三条自曝缺口）、批次划分与依赖正确。以下裁决随实施令生效。

### 裁决

| # | 裁决 | 附加条件 |
|---|------|----------|
| D-H1 | **批准渐进式披露升级** | 向后兼容单文件 YAML（存量 11 个不动）；三层加载器加开关回退（升级失败可回旧加载器）；每 Skill 元数据 ≤200 token |
| D-H2 | **仅 fetch 先行** | filesystem 无限期缓批（场景弱+攻击面大）；fetch 出口白名单初始化为空——按需逐域名审批 |
| D-H3 | **真实 Python 数据分析工具** | write_high 强制人审 + 沙箱执行 + 产物回传受控目录 + 首月影子运行（只审计不回用户，验收执行质量后切正式） |
| D-H4 | **管理端可配** | 词表存 agent_customizations（agent:observability 同域参数模式），改动走定制审批留痕 |
| D-H5 | **本期 1 条工作流** | 监理文档工作流必须含人审节点（AI 草稿→人工确认→定稿），与 D-C 裁决一致 |

### 委员会补充要求（计划未覆盖，随批次并入）

1. **意图分类的评测必须含恶意用例**——意图层是输入面，注入测试集的 40 例须同步跑意图分类（验证注入不被分类为合法 action 直通）；
2. **渐进式披露的第 3 层（资源/脚本）沿用沙箱治理**——scripts 执行一律走沙箱执行器，不得绕行；
3. **矩阵中的"后台 33 Agent"不强制全覆盖**——按高频 Top6 补 Skill 即可（资产化按需，避免一次性 33 个空壳 YAML）；
4. **每批次完成报销项**，第三批完成时同步输出"意图分类准确率报告"（golden + 注入双口径）。

**签署**：平台架构组 ✓ / 产品体验组 ✓ / 内控合规组 ✓

### 实施令

批准按批次一→二→三顺序实施（≈6.5 人日），D-H1~H5 附加条件随批次生效；批次三的意图准确率报告与沙箱首验为方案关闭前置件。
