## 1. 背景与问题陈述

### 1.1 现状盘点（实测）

已具备：33 个后台 Agent（治理面单通道、37 工具全分级）、6 个对话入口、18 个 Skill、3 条 DSL 工作流、意图识别输入层、SSE 流式、沙箱执行器、审计/回滚/告警全链。

**四个结构性缺口**（甲方指示的迭代方向）：

| # | 缺口 | 现状证据 |
|---|------|----------|
| G1 | **Agent 无"专家"画像** | Agent = 基座 + 工具集；岗位方法论、领域 SOP、检查清单散落在 instructions 字符串与 18 个 Skill 中，无结构化专家档案，无法回答"这位专家凭什么可信" |
| G2 | **多 Agent 协作只有单一星形** | Supervisor（总调度）→ 子域 Agent 的委派-综合星形拓扑；无评审会、辩论、管道式流水线等团队协作形态，复杂决策（大额采购/上线审计）缺"多专家背书"机制 |
| G3 | **Agent 间/对外无标准互通协议** | Agent 间协作全靠进程内事件总线；对外（其他企业系统/第三方 Agent）零标准接口——MCP 解决了"Agent↔工具"，"Agent↔Agent"仍是私有协议 |
| G4 | **工作流是代码资产而非流程资产** | 3 条 DSL 工作流硬编码于 BUILTIN_DSL；无子流程/并行网关/流程模板库；业务人员无法编排"企业工作流程" |

### 1.2 开源调研（2026-10 核实）

| 开源项目 | 核心机制 | 对本项目的可借鉴点 | 采纳方式 |
|----------|----------|--------------------|----------|
| **AgentScope 2.0**（[agentscope-ai/agentscope](https://github.com/agentscope-ai/agentscope)，Alibaba，Apache-2.0） | 消息中心（MsgHub）广播、Pipeline 管道、Studio 可视化追踪、运行时沙箱、GoalPipeline 目标驱动 | 专家团**通信内核**的拓扑语义（广播/点对点/管道）；**Studio 式团级 Trace**（发言/共识/异议时间线）；运行时沙箱思路（已有） | **借鉴思想自研薄层**——不引入框架依赖（治理面单通道与第三方框架的事件循环/消息模型冲突，铁律 07：框架当库不当架构） |
| **OctoTools**（[octotools/octotools](https://github.com/octotools/octotools)，Stanford，BSD-3） | **Tool Card**（工具元数据卡：功能/输入输出/用法）、**Planner**（子目标分解+工具选择）、**Executor**（Python 步骤执行）、**Contextualization**（历史轨迹迭代精化） | 专家的**规划-执行-上下文三分离**角色化；Tool Card 标准化（本项目 MCP descriptor + effects_fn 已有雏形 → 升级为专家工具卡） | **借鉴角色分离与卡片规范**，Planner/Executor 由治理面通道承载 |
| **ACP → A2A 融合**（IBM/BeeAI 提出 → [Linux Foundation A2A 项目](https://www.prnewswire.com/news-releases/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents-302488265.html)） | Agent Card 自描述、任务生命周期、消息+Artifact；REST/HTTP、离线异步 | 对外网关采用 **A2A 语义**（Agent Card/Task/Message/Artifact）——ACP 语义并入 A2A 是 2025 明确趋势，避免押注已融合协议 | **自研 A2A 兼容网关**（子集实现，不做完整协议栈） |

> **判断口诀**（知识库）：动作→Tool；方法→Skill；上下文要隔离→SubAgent；事实→RAG；**跨系统互信→A2A**。

## 2. 目标与非目标

### 目标

1. **专家体系**：Agent 之上叠加"专家"角色层——结构化岗位档案（方法论/SOP/技能集/工具白名单/预算/KPI），可注册、可发现、可评鉴；
2. **专家团**：以章程定义的团队协作（成员/主持/拓扑/升级路径），支持评审会、辩论、管道、并行分工四种形态，产出物（结论/报告/决策建议）带完整背书链；
3. **ACP/A2A 网关**：对外以标准协议暴露本系统 Agent（Agent Card + 任务生命周期），对内消费外部 Agent（白名单+治理面桥接）；
4. **企业工作流编排**：工作流升级为流程资产——子流程、并行网关、版本化、与专家团互相调用；
5. **全程治理不旁路**：专家团每一步、ACP 每一个入站请求，都经治理面单通道（RBAC/审计/预算/回滚语义不变）。

### 非目标

- 不引入 AgentScope/OctoTools 作为运行时依赖（仅借鉴思想，铁律 07）；
- 不做多租户 SaaS 化；不做跨企业 Agent 市场；
- 不追求 A2A 全协议栈（先做 Agent Card + Task 子集，附录标注差异）；
- 不改变既有 6 对话入口的交互形态（专家团是新入口，不替换旧入口）。

## 3. 用户与场景

### 场景一：月度经营分析专家团（管道+分工）

CFO 发起"10 月经营分析"→ 团长（总调度）分解：财务专家出利润表 → 采购专家出成本异动 → 销售专家出收入分析 → 风控专家风险标注 → 团长汇总成报告（docx）→ CFO 审批。各步骤过治理面、产出物带各专家背书。

### 场景二：大额采购决策评审会（评审会拓扑）

采购专家提议供应商 A → 团长召集评审会：风控专家（信用风险）、法务专家（合同条款）、财务专家（资金占用）逐个出**结构化意见**（支持/反对/条件）→ 主持汇总共识与异议 → 人审终裁。

### 场景三：上线审计辩论（辩论拓扑）

上线审计中安全专家与开发专家就"是否可上线"意见相左 → 辩论拓扑（各 2 轮交叉质证）→ 团长按证据强度裁决 → 异议记录入档。

### 场景四：外部系统消费本系统 Agent（ACP/A2A 出站）

集团 OA 通过 A2A 协议向本系统"报销专家"提交报销任务 → 网关验证白名单+预算 → Agent 处理（治理面全链）→ Artifact（报销单+回执）按 A2A 语义返回。

## 4. 总体方案

### 4.1 架构（三层货架视角落位）

```
编排层  专家团引擎（Team Engine：章程/拓扑/主持/共识）
         │  每步经治理面（不旁路）
方法层  专家档案（Expert Profile：方法论 SOP + Skill 集 + 检查清单）
         │  复用既有 Skill 加载器（渐进式披露）
原子层  37 治理面工具 + MCP 桥接（word/fetch/只读查询…）+ 沙箱
互通层  A2A 网关（Agent Card / Task 生命周期 / 入站治理）
```

### 4.2 与治理面的关系（安全边界，逐条锁死）

| 边界 | 约束 |
|------|------|
| 专家团内每步工具调用 | 仍走 governor.execute 单通道——专家团是编排语义，不是新执行通道 |
| 团级预算 | team 预算 ≤ Σ成员预算（新增 team:{id} 预算键，超限熔断全团） |
| A2A 入站 | 调用方白名单 + 每调用方日预算 + 治理面 RBAC 映射到"虚拟身份"（A2A caller → ERP 虚拟用户，权限取最小交集） |
| A2A 出站 | 消费外部 Agent = 治理面 readonly 工具（external agent 白名单 + 超时 + 输出过 untrusted 封装） |
| 专家团产出物 | Artifact 落受控目录 + 审计 + "AI 生成草稿"标注（延续 D-C 裁决） |

## 5. 功能需求（FR，可验收口径）

### FR-E 专家体系（里程碑 M1）

| FR | 需求 | 验收 |
|----|------|------|
| FR-E1 | 专家档案（YAML+DB）：岗位/职责边界/方法论 SOP（渐进式披露三层）/技能集（skill 名单）/工具白名单（治理面子集）/预算/KPI | 档案校验器 + 管理端 CRUD（agent_customizations 模式） |
| FR-E2 | 专家注册与发现：档案注册进专家目录（Agent Card 雏形：name/description/skills/tools/预算）；`experts/list` 可查 | 6 个对话 Agent 全部档案化 + 目录 API |
| FR-E3 | 专家模板库：预置 8 个企业专家模板（监理/财务/采购/销售/风控/法务/人力/IT 运维） | 模板实例化→对话 Agent 可用 |
| FR-E4 | 专家 KPI：调用次数/成功率/人工修正率/预算消耗——进全成本报表 | 报表页可查 |

### FR-T 专家团（里程碑 M2）

| FR | 需求 | 验收 |
|----|------|------|
| FR-T1 | 团队章程（Team Charter YAML）：成员（专家名单+角色）、拓扑、主持规则、升级路径（人审触发条件）、预算 | 章程校验器 + 管理端 CRUD |
| FR-T2 | 四种拓扑引擎：评审会（逐个结构化意见→共识/异议汇总）、辩论（交叉质证 N 轮→裁决）、管道（顺序分工+交接校验）、并行分工（分片汇总） | 四拓扑各一条 golden 场景 UAT |
| FR-T3 | 团队运行件：召集/主持（团长=Supervisor 复用）/发言轮转/预算熔断/异常降级（成员失败→团长接管重分派） | 故障注入演练 |
| FR-T4 | 产出物：结论+分歧行+各专家背书链（trace_id 串联）+ Artifact（docx） | 产出物可溯源到每步发言 |
| FR-T5 | 团级 trace：发言时间线/共识/异议进 operation_logs（AgentScope Studio 式可视化） | 管理端时间线视图 |

### FR-C ACP/A2A 网关（里程碑 M3）

| FR | 需求 | 验收 |
|----|------|------|
| FR-C1 | Agent Card：`GET /.well-known/agent.json`（A2A 语义：能力/技能/鉴权方式/输入输出模式） | 外方可发现本系统 Agent |
| FR-C2 | 任务生命周期：`POST /a2a/tasks`（受理→running→completed/failed，Artifact 回传）+ 查询/取消 | 全生命周期状态机 + 超时语义 |
| FR-C3 | 入站治理：调用方白名单、每调用方预算、RBAC 映射虚拟身份、全量审计 | 越权/超预算用例被拒且有审计 |
| FR-C4 | 出站消费：外部 Agent 注册（白名单）→ readonly 治理面工具桥接（超时/输出 untrusted 封装） | 外部 Agent 结果经治理面可查 |

### FR-W 工作流编排升级（里程碑 M4）

| FR | 需求 | 验收 |

## 9. 风险与开放问题

| # | 风险 | 对策 |
|---|------|------|
| R1 | 多专家串行 LLM 成本与延迟（评审会 4 专家×2 轮 = 8 次调用） | 团级预算硬护栏 + 主持可提前收敛 + 发言摘要压缩上下文 |
| R2 | 意见趋同（专家假共识） | 拓扑内强制"至少一条异议或风险标注"，团长裁决必须引用分歧 |
| R3 | A2A 网关成为新攻击面 | 三闸门先行 + 入站任务全审计 + 沙箱执行外部代码默认禁用 |
| R4 | 专家档案与 Skill/工具漂移 | 档案校验器复用 skill 白名单机制；档案变更走定制审批 |
| R5 | 协作会话并行开发的合并冲突 | PRD 定稿后建立开发分支约定，各批次独立分支 |

**开放问题**：①"Octo"按 OctoTools 解读——若甲方另有所指（Octopus 等）请指出；②A2A 网关的部署边界（并入现有 8000 进程 vs 独立进程）——建议并入现有进程+独立路由前缀。
