# Agent 定制化平台迭代路线图（管理端可配置化）

- **文档日期**：2026-09-19
- **文档性质**：供项目所有者审批的迭代计划——**审批通过后按 Phase F1 启动**
- **前置状态**：Agent 生产化路线图（roadmap-agent-production-2026-09-19.md）Phase A~E 全部交付；
  24+ 治理面工具、3 条工作流、6 个 Skill、Supervisor 协同、MCP 出口均已上线，
  但全部为**代码/文件硬编码**——业务调整需要改代码发版
- **本路线图主题**：把编排资产从"代码资产"升级为"**管理端可配置的运行时资产**"——
  管理员在 CIOAdmin 界面完成子 Agent 定制化改造：**业务链路改造、工作流改造、
  MCP 与 Skill 定制化配置、人在环节点配置**，全程带审计、审批与灰度，不改代码不发版

---

## 1. 现状盘点（定制化视角的能力与缺口）

### 1.1 已有基础（可直接复用的地基）

| 资产 | 现状 | 定制化改造中的角色 |
|------|------|------------------|
| 治理面 AgentGovernor | 工具调用统一通道（RBAC/schema/dry-run/分级审批/审计/限流） | **定制生效的执行点**——配置覆盖在此读取即可全局生效 |
| 工具注册表 tools_v2 | 进程内注册 + 目录 API（GET /agent-ops/tools）+ 调用统计 | 工具启停/风险分级改造的操作对象 |
| Skill 加载器 | YAML 目录**热加载**（文件级）、惰性白名单校验、目录 API | 管理端编辑器直接写目录即可生效（加载器零改造） |
| 工作流引擎 | 3 条硬编码 builder + 确定性节点 + interrupt 人审门 + Checkpointer | DSL 化的运行时底座；内置模板保留为"出厂模板" |
| 审批链路 | agent_approval_requests + decide 路由 + 审批中心前端 | 定制变更自身的审批通道（放宽类变更走此流程） |
| Redis 版本信号 | RBAC 跨实例版本失效（ensure_fresh 模式） | **定制热更新广播**——同模式实现多实例配置失效 |
| CIOAdmin 页面 | 已有 Agent 状态/系统配置/备份等管理区块 | 定制中心的 UI 落点（新增"Agent 定制中心"区块） |
| 审计哈希链 | 全量操作审计、重启续链 | 定制变更 100% 审计（谁/何时/改了什么/旧值新值） |
| 评测集 runner | 50 用例 + 在线模式（脚本/真 LLM 双模式） | **定制效果验证器**——配置变更后按域跑分对比 |

### 1.2 核心缺口（为什么要做这一期）

1. **配置零持久化**：人审分级阈值（如报销 5000 元免审线）、预算上限等硬编码在代码/配置文件，业务调整需发版；
2. **无管理端操作面**：工具启停/风险分级调整、Skill 内容修改、外部 MCP 接入只能改文件或调 API 脚本，业务管理员无法自助操作；
3. **工作流不可配**：三条跨域流程节点/阈值/审批路由写死，业务链路改造 = 重写 builder；
4. **人在环节点不可配**：审批人路由（谁审什么金额区间）、超时策略、免审线全局一刀切，无法按部门/单据类型差异化；
5. **无版本与灰度**：任何配置变更立即全局生效，无历史、无回滚、无灰度。

## 2. 总体设计

### 2.1 分层模型：内置默认 → 定制覆盖 → 运行时合成

```
┌─────────────── 管理端（CIOAdmin · Agent 定制中心）────────────────┐
│ 工具管理 │ 工作流设计器 │ Skill 编辑器 │ 人在环配置 │ Agent 人设      │
└──────────────────────────┬───────────────────────────────────────┘
                           │ PUT /agent-ops/customizations/*（agent:manage）
                           │ 放宽类变更 → 走审批（interrupt 人审）
                           ▼
┌─────────────── 定制层（MySQL 持久化 + 版本历史）──────────────────┐
│ agent_customizations：type/tool|workflow|skill|gate|agent        │
│ + overrides JSON + enabled + version + updated_by + 审计哈希链     │
└──────────────────────────┬───────────────────────────────────────┘
                           │ Redis 版本信号（erp:cust:version）失效缓存
                           ▼
┌─────────────── 运行时合成（各执行点读取：内置默认 ⊕ 定制覆盖）──────┐
│ governor.execute：工具启停/风险分级/参数默认值                      │
│ workflows 运行器：阈值/审批路由/节点参数（DSL 实例）                │
│ skills 加载器：白名单/指令模板/护栏                                 │
│ supervisor/场景图：per-agent 预算/模型参数/业务上下文开关            │
└───────────────────────────────────────────────────────────────────┘
```

**四条不可突破的治理红线**（设计层面锁死，管理端 UI 只暴露允许项）：
1. **治理节点不可禁用**：工作流中治理面校验/审计/dry-run 节点不可删除或跳过，只能调参数；
2. **放宽类变更必须审批**：write_low→write_high 收紧可即时生效；反向放宽
   （write_high→write_low、免审阈值上调、新外部 MCP 接入）必须走人审后生效；
3. **定制变更 100% 审计**：旧值/新值/操作人/审批人全量入审计哈希链；
4. **配置带版本与回滚**：每次变更生成版本记录，一键回滚到任意历史版本。

### 2.2 热更新机制（复用已验证模式）

定制写入 MySQL → `INCR erp:cust:version`（Redis）→ 各执行点
`ensure_fresh()`（5 秒节流，复用 RBAC 版本信号模式）检测漂移 → 重载定制缓存。
多实例部署下全部实例 5 秒内收敛，无需重启。

## 3. 分阶段路线图（5 阶段，约 10 人周）

### Phase F1：定制化配置中心——治理面可配（约 2 人周）

**目标**：建立定制层（持久化+版本+审批路由），第一批治理面配置管理端可改。

**退出标准（全部可验证）**：
1. 管理端将任一工具 `write_low→write_high`（收紧）→ 5 秒内全部实例生效，该工具
   后续调用进入人审门（集成测试断言）；反向放宽需审批通过后才生效；
2. 免审阈值（如报销 5000 元线）管理端可调，生效后新单据按新阈值路由；
3. 工具临时停用（如销售下单工具下线）→ 调用返回明确的"已停用"错误，审计记录；
4. 每次变更产生版本记录，回滚到历史版本 API 可用且生效；
5. 多实例收敛 ≤5 秒（Redis 版本信号）；定制变更全量审计。

| # | 任务 | 说明 |
|---|------|------|
| F1.1 | `agent_customizations` 表（type/target/enabled/overrides JSON/version/updated_by）+ 版本历史表，bootstrap 建表 | 定制层持久化 |
| F1.2 | CustomizationService：读取合成（默认⊕覆盖）、缓存、版本信号失效、变更 API（含放宽类审批路由） | 核心服务 |
| F1.3 | 治理面接入：governor.execute 读取工具启停/风险覆盖/免审阈值覆盖 | 生效点 |
| F1.4 | 管理端 API：GET/PUT /agent-ops/customizations/*（agent:manage + 放宽审批） | 供前端 |
| F1.5 | CIOAdmin"Agent 定制中心"一期：工具列表（启停开关/风险分级/编辑）+ 变更历史 | UI |
| F1.6 | 测试：收紧即时生效/放宽审批后生效/回滚/多实例信号/红线（治理节点不可禁用） | CI |

### Phase F2：Agent 级定制与业务链路参数化（约 2 人周）

**目标**：单个 Agent 的人设/预算/业务链路参数管理端可配，不改代码。

**退出标准**：
1. 修改某 Agent 系统提示词（人设模板）→ 该 Agent 下轮对话即按新人设回答（评测集跑分留档）；
2. per-Agent 覆盖：LLM 温度/日 token 预算/工具子集（该 Agent 可用工具清单）管理端可配；
3. 业务链路参数化首批：报销流免审阈值、必填字段（是否强制发票）、上下文采集开关
   （该域编排注入哪些业务数据源）管理端可调；
4. 审批人路由矩阵 v1：按「单据类型 × 金额区间 → 审批角色」映射表管理端可配，
   write_high 中断产生的审批任务按矩阵路由（替代当前全员可见）；
5. 全部覆盖项有人设/链路变更的评测对比报告（变更前后评测分）。

| # | 任务 | 说明 |
|---|------|------|
| F2.1 | Agent 人设模板定制（system prompt 覆盖 + 模板变量）注入场景图 | runtime 支持 |
| F2.2 | per-Agent 覆盖：模型参数/预算/工具白名单子集（治理面执行点过滤） | 复用 F1 定制层 |
| F2.3 | 业务链路参数化框架：域参数 schema 声明式定义（每域一份参数清单）+ 管理端表单自动生成 | 参数化核心 |
| F2.4 | 首批落地：报销流阈值/必填项/上下文开关 | 参数化样板 |
| F2.5 | 审批人路由矩阵（type×amount→role）+ decide 路由改造 + 审批中心按角色过滤 | 人在环配置 v1 |
| F2.6 | 定制效果评测：变更前后自动跑该域评测集，报告入管理端 | 防改坏 |
| F2.7 | 测试 + UI（Agent 定制中心二期：Agent 卡片式编辑） | CI |

### Phase F3：工作流改造——DSL 化与人在环节点配置（约 2.5 人周）

**目标**：工作流从硬编码 builder 升级为声明式 DSL，管理端可视化改造业务链路。

**退出标准**：
1. 工作流 DSL（JSON/YAML）：节点（类型：task/gate/approve/end）/边/条件路由/
   人审参数（阈值/审批角色/超时）/补偿映射声明式定义；
2. **DSL 校验器**：治理节点缺失、补偿未映射、环检测、未知工具引用 → 拒绝发布；
3. 现有 3 条工作流（报销审批/采购到支付/合同审批）迁移为 DSL 实例，
   与硬编码版**行为等价**（同一测试双跑断言）；
4. 管理端可视化设计器 v1：表单式节点编辑 + 流程图预览 + 版本发布/回滚/灰度
   （新旧版本按比例路由）；人在环节点：阈值/审批角色/超时 per-node 可配；
5. DSL 发布走审批（变更影响面大），发布后自动跑关联评测集。

| # | 任务 | 说明 |
|---|------|------|
| F3.1 | 工作流 DSL schema + 校验器（安全：仅白名单节点类型/工具引用） | DSL 核心 |
| F3.2 | DSL 运行器：从定义动态编译 StateGraph（复用 Checkpointer/审计） | 替代硬编码 builder |
| F3.3 | 3 条内置工作流迁移为 DSL 实例（行为等价双跑测试） | 存量迁移 |
| F3.4 | 人在环节点配置：per-node 阈值/审批角色（对接 F2.5 路由矩阵）/超时策略 | 人在环可配 |
| F3.5 | 版本管理：发布/历史/回滚/灰度比例路由 | 生产安全 |
| F3.6 | 管理端设计器 v1（表单 + 流程预览；拖拽画布列为后续增强） | UI |
| F3.7 | 测试：DSL 校验拒绝矩阵/等价双跑/灰度路由/人审参数生效 | CI |

### Phase F4：MCP 与 Skill 定制化（约 2 人周）

**目标**：MCP 接入与 Skill 内容管理端自助化，业务管理员不碰文件。

**退出标准**：
1. 外部 MCP Server 管理端 CRUD + 连接测试 + 工具发现预览 + 白名单勾选 →
   保存后自动桥接为治理面工具（放宽类需审批）；
2. MCP 出口配置：暴露域/工具启停管理端可配（token 鉴权不变）；
3. Skill 管理端编辑器：表单化编辑（指令模板/工具白名单勾选/护栏参数）→
   写 YAML 目录 → 热加载生效（复用现有加载器）；启用/停用开关；
4. Skill 版本历史与回滚；Skill 导出/导入（JSON 模板，为后续"技能市场"预留）；
5. 全部变更审计 + 评测验证（skill 变更后自动跑关联域评测）。

|---|------|------|

| F4.2 | 外部工具桥接联动（勾选→register_external_tools 增量注册，放宽审批） | 复用 D3 桥接器 |

## 5. 风险与应对

| 风险 | 应对 |
|------|------|
| 定制放宽类变更被滥用（管理员随意降低审批级别） | 放宽类变更强制走审批（由 administrator 之外的角色批准）+ 全量审计 + 定期抽样报告 |
| 热更新多实例不一致 | 复用 RBAC 版本信号模式（已验证）；收敛时间纳入 F1 退出标准 |
| DSL 表达力不足/过强（安全） | 白名单节点类型 + 校验器拒绝非法结构 + 治理节点不可删除红线；表达力按业务需求迭代 |
| 定制层故障拖垮运行时 | 读取失败自动回退内置默认（显式告警）；定制表损坏可清空回出厂 |
| 管理端误操作（改错提示词致 Agent 质量下降） | 变更自动跑关联评测集出对比报告（F2.6/F4.6），低分阻断发布（可配置强制） |
| 与既有硬编码共存混乱 | 内置默认与定制覆盖分层清晰（默认代码不可改，覆盖层可删可回滚）；3 条工作流双跑等价迁移 |
| 范围蔓延（画布编辑器/多租户/A2A） | 拖拽画布、多租户、A2A 明确列为后续增强，本路线图不含 |

## 6. 成功度量（全部可自动化验证）

| 指标 | 基线 | 目标（M-F5 出口） |
|------|------|------------------|
| 业务参数调整（免审线/预算/审批路由）落地周期 | 改代码+发版（天级） | **管理端操作 ≤5 分钟生效** |
| 写工具启停/分级调整生效时间 | 不支持 | ≤5 秒全实例收敛 |
| 工作流业务链路改造 | 重写代码 | DSL 表单化改造 ≤30 分钟 + 自动评测 |
| 外部 MCP 接入 | 改配置文件+重启 | 管理端 CRUD+测试+白名单 ≤15 分钟 |
| Skill 内容迭代 | 手工改 YAML | 管理端编辑器 + 热加载 ≤1 分钟 + 评测对比 |
| 定制变更审计覆盖率 | — | **100%**（旧值/新值/审批人） |
| 定制层故障 | — | 自动回退内置默认（0 不可用） |
| 评测集 | 50 用例手动跑 | 按域一键触发 + 历史趋势 |

## 7. 明确不做（范围控制）

- 不做工作流**拖拽画布**编辑器（v1 表单化，画布列为后续增强）；
- 不做多租户（定制层预留 tenant 维度字段但不实现隔离）；
- 不做 A2A 协议/Agent 间自动谈判（委派仍由 Supervisor 确定性路由）；
- 不做跨系统 UI 低代码平台（仅 Agent 编排资产定制，不涉及前端页面搭建）；
- 不允许通过定制层绕过治理红线（治理节点/审计/补偿不可禁用——schema 层锁死）。
