- **作者**：乙方产品

## 1. 背景与问题陈述

### 1.1 现状（四期迭代后的资产与债）

四期迭代（生产化 A~E/定制化 F1~F5/可观测与沙箱 G1~G6 + 套件完善）沉淀了经过 1521 例测试验证的核心资产：**治理面单通道**（RBAC→审批→补偿→审计哈希链）、回滚账本、工具协议 v2（五钩子）、意图识别输入层、沙箱执行器、事件总线（并发派发）、操作日志/审计查询。但同时：

1. **应用层形态老化**：前后端围绕"6 个对话入口 + 管理台"演进，页面/数据模型/角色体系碎片化，无法承载下方 §2 的完整企业协作形态；
2. **知识体系缺失**：无个人知识库（工作技巧/技术能力沉淀）、无公文模板库、无部门级知识分层；
3. **实时资料库缺位**：发票/报销/报税/合同/资产/库存台账/工资单等日常运行文档分散在各业务模块，无统一"岗位权限查看编辑 + 生成后防篡改（时间戳/水印/不可抵赖）+ 删改须审批"的资料库语义；
4. **IM 协作缺位**：无全员群/部门群，无数字分身私聊；
5. **能力市场缺位**：专家/Skill/MCP/ACP 无统一上架、审核、分发、评价体系；
6. **决策层视图缺位**：无分管领导看板、无董事长全域驾驶舱（数字孪生大屏）与战略决策建议。

### 1.2 甲方指示

采用腾讯 **Octop** 与阿里 **AgentScope** 为借鉴和能力底座，**全面重构**前后端，按 §2 新形态交付，角色体系按 §6 五层落地。

```
┌─ 后端（Octop 式模块化）─────────────────────────────────────┐

```

## 3. 重构策略与内核处置（关键决策 §8 D-R1）

**乙方建议：内核库保留 + 应用层全面重构**。治理面/审计哈希链/回滚账本/工具协议/意图层/沙箱是 1521 例测试验证过的安全底座，"抛弃设计"指的是**应用层形态与数据模型**，这些安全内核应以 `erp-core` 库形态适配进新架构（适配层预计 0.5~1 周）。若甲方裁决激进全弃（含治理面重写），工期 +4 周 且安全回归风险自担——本建议基于 G 系评审"安全机制拉满"的既有结论。

其余重构决策：前端保留 React 技术栈但**全新应用壳与页面族**（D-R2）；数据库**全新 schema**（不复用旧 58 表，按新域建模；旧库只读归档）；旧系统**并运行渡期 2 周**后硬切（D-R6）。

## 4. 用户与角色体系（五层，权限矩阵）

| 角色 | 权限摘要 |
|------|----------|
| **系统管理员** | 角色与权限体系管理；用户增删改查；能力市场（四市场）增删改查与更新维护；系统日志与运行参数查看审计（运维/排障） |
| **普通员工** | 个人知识库增删改查；已下载/使用的专家、Skill 等能力管理；Agent 对话 |
| **部门管理员** | 普通员工全部 + 部门知识库/部门专家与专家团/Skill 的增删改查 + 部门用户增删改查 + 部门保密资料的权限审批与增删改查 |
| **主管领导**（CEO/CFO/CIO/CTO 等） | 部门管理员全部 + 其分管部门的运行分析看板 |
| **董事长** | 全域权限 + **全域驾驶舱看板（数字孪生大屏）**：公司主要数据对比分析 + Agent 战略决策建议 |

（权限实现：沿用治理面 RBAC 引擎 + 资源:动作矩阵，五角色为预设模板；细粒度授权走既有审批体系。）

## 5. 功能需求（FR 编号）

### 5.1 对话域（FR-C）

| FR | 需求 |
|----|------|
| FR-C1 | 统一对话入口：首页对话框（流式输出、意图识别输入层、thinking/待办卡片联动） |
| FR-C2 | 专家对话：按 §5.4 专家运行时（专家=角色化 Agent：岗位 Prompt+Skill 集+工具白名单+预算） |
| FR-C3 | 专家团对话：按章程编排的团队协作（评审会/辩论/管道/并行分工四拓扑），产出物带背书链 |
| FR-C4 | Skill 对话：命中 Skill 的任务按渐进式披露加载（元数据→指令→资源） |
| FR-C5 | MCP 工具对话：白名单 MCP 工具经治理面桥接（readonly 先行） |
| FR-C6 | ACP 网关：Agent↔Agent 通信（对内：专家团互调；对外：A2A 兼容端点） |

### 5.2 知识库域（FR-K）

| FR | 需求 |
|----|------|
| FR-K1 | **个人知识库**：每员工私有空间（工作技巧、技术能力、经验沉淀），增删改查 + 全文检索 + 标签 |
| FR-K2 | **公文模板库**：公司级公文模板（监理大纲/报告/纪要/合同…），模板→AI 起草→人审定稿 |
| FR-K3 | **部门知识库**：部门级共享知识，部门管理员维护；跨部门访问须审批 |
| FR-K4 | 知识检索：混合检索（全文+语义）按知识域隔离（个人/部门/公司三层可见性） |
| FR-K5 | 知识→对话联动：对话中 @知识 或自动检索命中，答案带来源引用 |

### 5.3 实时资料库域（FR-D）——不可抵赖文档链

| FR | 需求 |
|----|------|
| FR-D1 | 资料类型全覆盖：发票、报销单、报税记录、项目合同、资产卡片、实时库存与出入库台账、工资单等日常运行文档 |
| FR-D2 | **岗位权限查看/编辑**：按角色×部门×资料类型三维矩阵（服务端强制，非前端隐藏） |
| FR-D3 | **定稿防篡改**：文档"最终生成"时落时间戳（服务端可信时钟）+ 哈希入审计链 + 可见水印（责任人/时间/编号）+ 隐式水印（trace_id）——**不可抵赖** |
| FR-D4 | **删改须审批**：定稿文档的修改/删除 → 部门管理员审批 → 审批通过后生成**新版本**（旧版本留存不可删，全版本链可追溯） |
| FR-D5 | 资料生成：业务系统事件自动生成（报销单/出入库台账）+ AI 辅助填报（发票解析等既有能力接入） |

### 5.4 IM 协作域（FR-M）

| FR | 需求 |
|----|------|
| FR-M1 | 群聊：公司全体群 + 部门群（自动建群/成员同步） |
| FR-M2 | 私聊：员工互聊 |
| FR-M3 | **数字分身私聊**：每员工一个数字分身（个人知识库+岗位技能驱动）；员工可与他人分身发起私聊（分身代答：基于对方知识库的授权范围回答）；**分身私聊内容仅部门管理员可查看** |
| FR-M4 | IM 内 Agent 卡片：群/私聊中 @专家 即席调用，结果以卡片回流 |

### 5.5 待办域（FR-T）

| FR | 需求 |
|----|------|
| FR-T1 | 首页对话框下方**待办卡片**：审批待办/任务待办/提醒，按来源（工作流/审批/IM 提及）聚合 |
| FR-T2 | 待办点击即达：跳转对应处理界面或对话上下文 |

### 5.6 能力市场域（FR-MKT）

| FR | 需求 |
|----|------|
| FR-MKT1 | **四大市场**：专家市场、专家团市场、Skill 市场、MCP/ACP 市场（统一货架、分类、搜索、评价） |
| FR-MKT2 | 系统管理员统一维护：上架/下架/更新/版本管理 |
| FR-MKT3 | **员工上传通道**：员工将使用效果良好的 Skill/专家/专家团 → 上传申请 → 管理员审核（含安全准入 6 检查）→ 全公司上架（含署名与使用统计） |

### 5.7 决策层域（FR-B）

| FR | 需求 |
|----|------|
| FR-B1 | 分管看板：CEO/CFO/CIO/CTO 各自分管部门的运行分析看板（经营/财务/IT/项目口径） |
| FR-B2 | **董事长全域驾驶舱**：数字孪生大屏——公司主要数据（经营/项目/资金/库存/人力/风险）对比分析与趋势 |
| FR-B3 | **战略决策建议**：Agent 基于全域数据生成下一阶段战略建议（带数据溯源），人审后进入正式渠道 |

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 对话首 token < 2s（流式）；资料库列表 < 500ms；驾驶舱聚合 < 3s（预聚合口径） |
| 安全 | 治理面内核库全量保留；资料不可抵赖链（§5.3）；A2A/ACP 三闸门；五角色 RBAC 服务端强制 |
| 合规 | 文档留存策略；审计哈希链全覆盖；个人知识库与分身私聊的隐私边界（部门管理员可见性按甲方明示口径） |
| 可靠 | 模块化单体部署（Octop 式），IM/对话网关无状态水平扩展；沙箱隔离 |

## 7. 里程碑（重构路线）

| 里程碑 | 内容 | 工期 |
|--------|------|------|
| M0 | erp-core 内核库抽取 + 新前后端骨架 + 五角色 RBAC 模板 + 全新 schema | 2 周 |
| M1 | 对话网关（流式/意图/专家）+ 知识库域（个人/模板/部门） | 2 周 |
| M2 | 资料库域（七类资料+权限矩阵+不可抵赖链）+ 待办卡片 | 2.5 周 |
| M3 | IM（群/私/数字分身）+ 能力市场（四市场+上传审核） | 2.5 周 |
| M4 | 看板（分管+驾驶舱大屏）+ 战略决策建议 + 专家团四拓扑 | 2.5 周 |
| M5 | 并运行渡 + UAT + 文档 + 硬切 | 1.5 周 |

**合计 ≈ 13 周**（含渡期；后续按里程碑逐个 UAT）。

## 8. 决策点（待甲方裁决）

| # | 决策点 | 选项 | 乙方建议 |
|---|--------|------|----------|
| D-R1 | 重构策略 | **内核库保留+应用层重构**（推荐）vs 激进全弃含治理面 | 内核保留——1521 测试验证的安全底座是最大资产 |
| D-R2 | 前端栈 | 沿用 React 全新壳（推荐）vs Next.js SSR | 沿用 React（团队已有栈，IM/流式经验可复用） |
| D-R3 | 不可抵赖实现 | 审计哈希链+水印（复用内核，推荐）vs 第三方存证服务 | 复用内核（零外部依赖；第三方存证列为远期可选） |
| D-R4 | 旧系统渡期 | 并运行 2 周后硬切（推荐）vs 长期并存 | 硬切——双轨数据漂移成本高 |
| D-R5 | ACP 实现 | A2A 兼容子集（推荐）vs 自定义 REST | A2A 兼容——生态趋势 |
| D-R6 | 数字分身知识边界 | 分身仅答对方**已授权公开**的知识条目（推荐）vs 全量 | 授权范围——隐私最小化 |

## 9. 风险与开放问题

| # | 风险 | 对策 |
|---|------|------|
| R1 | 重构期间业务断档 | 并运行渡期 + 数据迁移脚本 + 回滚预案 |
| R2 | 五角色权限矩阵遗漏 | 权限模板评审会专项 + 治理面 RBAC 矩阵全覆盖测试 |
| R3 | 数字分身隐私（分身代答泄露他人知识库） | 知识条目分级授权 + 分身回答审计抽检 |
| R4 | 不可抵赖水印被截图绕过 | 可见水印（威慑）+ 哈希链（司法口径）双层，诚实披露残余风险 |
| R5 | 工期（13 周）超预期 | 里程碑独立 UAT，可按 M0→M3 先交付核心闭环（对话+资料库+IM），市场与驾驶舱次期 |
| R6 | 环境漂移（PATH/依赖被外部改动） | 固定解释器 + 锁文件 + 启动自检脚本（教训已入库） |

**开放问题**：① Octop 的 IM 网关是否要求对接企业微信/钉钉（影响 M3 排期）；② 资料库七类文档的存量迁移范围（旧系统哪些数据入新库）；③ 驾驶舱"数字孪生"的视觉口径（2D 大屏 vs 3D 场景）。
